# v4.0.0

This release takes the raw Yahoo Finance responses out of the versioned database
([#57](https://github.com/rehanhaider/stocky/issues/57)). `stocky.db` now holds only the fields Stocky reads from them,
and the responses stay in a local cache file that Git ignores. The file shrinks from 40.9 MB to 11.1 MB.

## Breaking database changes

- **`yahoo_responses` is replaced by `yahoo_fields`.** The raw `all_modules` answers made up most of `stocky.db`, and
  every quarterly refetch rewrote them, adding about 30 MB of compressed history to each clone. `yahoo_fields` has one
  row per ticker, with the ticker, its exchange, `fetched_at`, and the 22 fields that `yahoo fields`, `yahoo enriched`,
  and `screen` show, such as `name`, `market_cap`, and `sector`. The [schema reference](../schema.md#the-yahoo_fields-table)
  lists every column and the module each comes from. A query that decoded `yahoo_responses.response_json` should read
  these columns instead:

  ```sql
  SELECT c.isin, c.nse_symbol, y.name, y.market_cap / 1e7 AS market_cap_crore, y.sector
  FROM consolidated c
  JOIN yahoo_fields y ON y.yahoo_symbol = c.yq_ns
  ORDER BY y.market_cap DESC
  LIMIT 10;
  ```

- **The raw responses live in `data/output/stocky_yahoo_cache.db`.** `stocky yahoo update` and
  `stocky yahoo import-cache` write each response there and its fields to `yahoo_fields`, in one transaction. The cache
  file is named after the database, so `--db-path scratch.db` uses `scratch_yahoo_cache.db` beside it. It is not
  committed and not attached to the release, so a clone has the fields but not the responses.
- **Schema number 2.** `PRAGMA user_version` reads `2`. The `consolidated` layout is unchanged, so a schema-1 file
  needs no rebuild for its `consolidated` reads. Stocky no longer reads an older file's `yahoo_responses` table: its
  tickers show as `missing` until `stocky yahoo update` fills `yahoo_fields`.
- **`yahoo_status` is `ok` or `missing`.** Only responses that name a listed security are ever saved, so the
  `unusable` value that `yahoo enriched` and `yahoo fields` used to report for an error or index answer no longer
  occurs. This database had no such responses.

## Other changes

- `screen`, `yahoo fields`, and `yahoo enriched` read the stored columns instead of decompressing and parsing every
  response, so an NSE screen of this database takes 0.11 s against 0.46 s before.
- `--missing-only` and `--stale-days` judge tickers by `yahoo_fields`, so an update in a fresh clone without the cache
  file fetches only what the database lacks.
- Pruning removes the fields and cached responses of tickers no longer in `consolidated` from both files, and vacuums
  each file that lost rows. A database without a cache file is pruned on its own.
- `stocky rebuild` no longer creates an empty Yahoo table.

## Included database

The versioned database is `data/output/stocky.db` in the repository at tag `v4.0.0`.
It is not attached as a separate release asset.

- SHA-256: `3bfe9e93702df14cf2f2ac9d1f32ac853588574c23aa2018017826f704b15a15`.

The data is the v3.0.0 database converted once, without a refetch, so the sources, row counts, and Yahoo fetch dates
are those of [v3.0.0](v3.0.0.md). The 7,513 stored responses each became one `yahoo_fields` row, and `yahoo enriched`
gives byte-for-byte the same JSON and CSV for both files: the number columns have no declared type, so an
integer market cap still prints as an integer.

| | v3.0.0 | v4.0.0 |
| --- | --- | --- |
| Yahoo table in `stocky.db` | `yahoo_responses`, 7,513 rows | `yahoo_fields`, 7,513 rows |
| File size | 40.9 MB | 11.1 MB |
| Gzipped | 29.6 MB | 3.7 MB |
| Schema number | 1 | 2 |

`stocky summary` passes every check; see [`data/output/refresh-summary.md`](../../data/output/refresh-summary.md).

The package metadata and `stocky version` both report `4.0.0`.
