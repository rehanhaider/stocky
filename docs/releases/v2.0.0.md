# v2.0.0

This release identifies the database column change introduced on 2026-10-03 in
[pull request #40](https://github.com/rehanhaider/stocky/pull/40).

## Breaking database changes

The `consolidated` table now stores Zerodha and Yahoo identifiers separately for each exchange.
Compared with the database layout before 2026-10-03:

| Previous column | Current columns |
| --- | --- |
| `zd_symbol` | `zd_ns`, `zd_bo` |
| `yq_symbol` | `yq_ns`, `yq_bo` |
| No BSE trading-symbol column | `bse_symbol` |

Queries that use `zd_symbol` or `yq_symbol` must use the appropriate exchange column instead.
For example, this query selects the Zerodha and Yahoo tickers for NSE-listed instruments:

```sql
SELECT isin, zd_ns, yq_ns
FROM consolidated
WHERE nse_symbol IS NOT NULL;
```

`yq_ns` and `yq_bo` contain full Yahoo tickers, including `.NS` and `.BO` respectively.
A symbol column is empty when that exchange does not list the instrument in the source bhavcopy.

## Included database

The versioned database is `data/output/stocky.db` in the repository at tag `v2.0.0`.
It is not attached as a separate release asset.

- Bhavcopy trade date: **2026-07-17**.
- `consolidated`: **4,707** rows.
- `yahoo_responses`: **8,338** rows after the 2026-10-03 cache refresh.

The bhavcopy trade date is the date of the exchange inputs used to build the instrument mappings,
not the date of the Yahoo cache refresh. Raw source files remain local inputs and are excluded from Git.

The package metadata and `stocky version` both report `2.0.0`.
